# Porting plan — gta4xlwifi (Exynos 9611)

Target: iOS 16.7.16 (20H392, iPhone X userland) + XNU xnu-8796 on the
Samsung Galaxy Tab S6 Lite Wi-Fi 2020 (SM-P610, `gta4xlwifi`).

## Bases — use both, for different layers

1. **dipa-studio/ios-sweet** — the generic layer. XNU patch series
   0001–0079 (toolchain, non-PAC arm64, AMFI/sandbox permissive mode,
   HFS+, IOSurface/IOMobileFramebuffer services, HID services,
   root-image builder, log ring). Most of this is device-independent.
2. **Floppikrob/ios-galaxy-s8** — the Exynos/Samsung layer, and the
   closest working precedent (Exynos 8895, boots to the lock screen).
   It is itself based on orhunnx/ios-a5xelte (Galaxy A5 2016).
   What transfers from it:
   - S-Boot loader pattern: our loader lives in the BOOT partition
     instead of a Linux Image (Samsung has no `fastboot boot`).
   - GIC-400 interrupt setup and 4 KiB pages (Exynos uses GIC-400,
     not the GICv3 of the Snapdragon base).
   - Timer setup (26 MHz on 8895; Exynos 9611 frequency to confirm
     from the live FDT — Gate 0).
   - The Exynos UFS host driver (the Qualcomm UFS driver in
     ios-sweet does not work on Exynos controllers).
   - S-Boot framebuffer via DECON: unmask the DECON trigger, draw
     into the framebuffer S-Boot leaves, native panel mode first
     (the S8 found iPhone X 1125x2436 presentation hangs; native
     resolution first, presentation later).
   - PMIC access over the SPEEDY bus (S2MPS family): rail power for
     touch, RTC read in the loader.
   - Touch pattern: Samsung touch controller over HSI2C, polled
     driver feeding HID digitizer events (S8 uses S6SY761; the
     gta4xlwifi touch chip is to be identified at Gate 0 — do not
     assume it is the same part).
   - Log recovery: ramoops (pmsg) + a log ring at the end of
     USERDATA, read back from TWRP/recovery.
3. **hackiosx.dev** — process reference (porting guide, compatibility
   notes). Exynos is rated the hard category there; plan accordingly.

## What is different on gta4xlwifi vs dreamlte (S8)

- Panel: 1200x2000 TFT (not AMOLED), DECON mode and splash behaviour
  to confirm from dumps.
- CPU: 4x Cortex-A73 + 4x Cortex-A53, all ARM-designed cores (no
  custom Mongoose cluster — the S8's big-cluster problem should not
  exist here; A73 cluster power-up still needs verification).
- PMIC / fuel gauge / charger: part numbers unknown until Gate 0
  (Exynos 9611 platforms commonly use an S2MPS-family PMIC, but this
  is **not** confirmed for this board — identify, don't assume).
- Touch + S Pen: touch controller and Wacom digitizer both unknown
  until Gate 0. S Pen is out of scope for the first stages.
- Wi-Fi/BT chip: unknown until Gate 0 (identify from the device
  tree / kernel config). No Samsung/Broadcom Wi-Fi driver exists in
  any ios-sweet-family port.
- GPU: Mali-G72 MP3 (Bifrost). The S8 port states the position
  plainly for its Mali-G71: it "cannot run iOS's Metal / AGX
  drivers, so hardware graphics is not realistic." CPU rendering
  (CoreAnimation software renderer, as in ios-sweet) is the plan.
  Panfrost exists for this GPU under Linux/Mesa, but there is no
  XNU port of it; GPU is a research item, not a gate.

## Gates

### Gate 0 — Dumps (device session, nothing flashed)
- `tools/gta-dump.sh` over ADB (and again in recovery with root):
  live FDT (`/sys/firmware/fdt`), stock boot image unpack, partition
  table (`/dev/block/by-name`), getprop, kernel config, dmesg.
- From the FDT/DTS: GIC base + version, timer frequency, reserved
  memory, UFS controller compatible, DECON/panel nodes, touch node,
  PMIC + fuel gauge nodes, Wi-Fi node.
- Back up at minimum: `boot`, `recovery`, `efs`/persist-equivalents
  for this tablet, `vbmeta`, and a full stock firmware reference
  (exact build fingerprint recorded in NOTES.md).
- Deliverable: `research/HARDWARE-MAP.md` completed from real data.

### Gate 1 — Our code runs
- Minimal shim (from the S8 loader) that draws a test pattern /
  prints to the framebuffer and writes a marker to ramoops, packed
  into the BOOT partition format and flashed via Odin/Heimdall.
- Success: test pattern on screen + marker readable in recovery,
  and stock boot image restores Android cleanly.

### Gate 2 — XNU early boot
- ios-sweet patch series rebased; new machine config for
  gta4xlwifi (GIC-400, 4 KiB pages, timer, MPIDR scheme).
- ADT generated by a `tools/mkadt_gta4xl.py` adapted from the S8 /
  sweet generators (iPhone X identity `iPhone10,3` / `D22AP`).
- Success: kernel log over the persistent ring shows XNU reaching
  IOKit / platform expert init without panic.

### Gate 3 — Storage + launchd
- Exynos UFS driver from the S8 port, adapted to the 9611
  controller addresses from Gate 0.
- iOS root image built with `tools/mkiosroot.sh` (IPSW downloaded
  by the user; never committed), written to USERDATA.
- Success: launchd + daemons up, log shows SpringBoard starting.

### Gate 4 — Display + touch -> lock screen
- Framebuffer copy path at native 1200x2000 first; throttled
  refresh like sweet's `sweetfb` approach.
- Touch driver for the identified controller (HSI2C pattern from
  the S8 port), HID digitizer events, rails via PMIC.
- Success: lock screen visible, swipe/tap reaches SpringBoard.

### Gate 5 — SMP + buttons + power
- Secondary cores via PSCI/PMU as on Exynos; A53 cluster first,
  then A73. Power/volume buttons as HID keys.

### Gate 6 — Stretch (in this order)
1. Battery: fuel-gauge readout -> real % + charging state
   (ios-sweet and the S8 port both ship a static stub; a real
   driver is already an improvement over both bases).
2. Wi-Fi: driver for the identified chip — large, no precedent
   in this family of ports for Samsung/Broadcom parts.
3. GPU: research only (see above).

## Rules

- Every boot attempt is logged in `NOTES.md` the same day, with the
  log excerpt — no silent retries.
- Nothing personal on the device: security is stubbed off.
- No Apple firmware, IPSW contents, partition backups or device
  serials in git, ever.
